## 2. Thiết kế Chức năng & Luật Nghiệp vụ (`[FR-xx]`)

- **`[FR-01]` Công thức Tính giờ Tăng ca (OT), Tự động Phân loại Hệ số & Chống trùng giờ (`ot-trip-calculator.ts`):**
  - **Quy tắc nghiệp vụ / Công thức:**
    - `startTime`, `endTime` định dạng `HH:mm` (cho phép `endTime = '24:00'`), bắt buộc `endTime > startTime` trong cùng `workDate`.
    - `totalHours = round2((endMinutes - startMinutes) / 60)`.
    - Giới hạn an toàn: tối thiểu `0.5` giờ (30 phút), tối đa `12` giờ / đơn / ngày (`400 INVALID_OT_DURATION`).
    - **Phân loại hệ số OT (`classifyOtRateType`):**
      1. Nếu `isHoliday === true` hoặc `workDate` nằm trong danh sách `holidays` → `HOLIDAY_300` (300%).
      2. Ngược lại, nếu `workDate` là Thứ 7 (`6`) hoặc Chủ nhật (`0`) → `WEEKEND_200` (200%).
      3. Ngược lại (Thứ 2 – Thứ 6) → `WEEKDAY_150` (150%).
    - **Chống trùng khung giờ (`doTimeRangesOverlap`):** Cùng nhân viên, cùng `workDate`, so sánh với các đơn có trạng thái `PENDING`/`APPROVED`. Nếu `aStart < bEnd && bStart < aEnd` → chặn `409 OT_TIME_OVERLAP` (cho phép nối tiếp sát giờ như `18:00–20:00` và `20:00–21:00`).

- **`[FR-02]` Vòng đời Đơn Tăng ca (OT) & Tích hợp Core Approval Engine:**
  - **Mô tả luồng:**
    - Nhân viên liên kết hồ sơ `employees` tạo đơn OT (`DRAFT` hoặc `submitNow: true`), cấp mã tự động duy nhất `OT-YYYY-NNNN`.
    - Khi gửi duyệt (`submitNow: true` hoặc `POST /overtimes/[id]/submit`): trong **1 MySQL Transaction**, kiểm tra trùng khung giờ, tra `directManagerUserId`, gọi `createApprovalRequest({ moduleCode: 'hrm', requestType: 'OVERTIME', entityType: 'overtime_requests', entityId, branchId, requesterId, directManagerUserId, title, summary, evalContext: { days: totalHours } }, trx)`, đổi `status = 'PENDING'` và lưu `approval_request_id`.
    - Khi người duyệt thao tác tại `/approvals`, hook `handleOvertimeApprovalCompletion` tự động cập nhật `overtime_requests.status` sang `APPROVED`/`REJECTED`/`CANCELLED` trong cùng Transaction.
    - Hủy đơn: `DRAFT` đổi thẳng sang `CANCELLED`; `PENDING` ủy quyền cho `actOnApprovalRequest(..., 'CANCEL')`.
  - **Quyền (RBAC / Data Scope):** Tái sử dụng `hrm.requests.create` (tạo/sửa/gửi/hủy của mình), `hrm.requests.read` (xem theo 4 tầng Data Scope `resolveEmployeeAccessScope`), `hrm.requests.export` (xuất Excel).

- **`[FR-03]` Vòng đời Đơn Công tác (`business_trip_requests`) & Tích hợp Core Approval Engine:**
  - **Mô tả luồng:**
    - Nhân viên nhập địa điểm (`destination`), từ ngày (`startDate`), đến ngày (`endDate`), chi phí dự kiến (`estimatedCost`, `DECIMAL(18,2)` >= 0), mục đích công tác (`purpose`).
    - Tự động tính `totalDays = endDate - startDate + 1` (chặn nếu `endDate < startDate` → `400 INVALID_TRIP_DATES`).
    - Chống trùng lịch công tác với các đơn `PENDING`/`APPROVED` khác của cùng nhân viên (`existing.start_date <= new.end_date && existing.end_date >= new.start_date` → `409 TRIP_DATE_OVERLAP`).
    - Cấp mã tự động duy nhất `CT-YYYY-NNNN`. Khi gửi duyệt, gọi `createApprovalRequest({ moduleCode: 'hrm', requestType: 'BUSINESS_TRIP', entityType: 'business_trip_requests', ..., evalContext: { days: totalDays, amount: estimatedCost } }, trx)`.
    - Hook `handleBusinessTripApprovalCompletion` tự động đồng bộ trạng thái `APPROVED`/`REJECTED`/`CANCELLED` trong cùng Transaction khi hoàn tất phê duyệt.

- **`[FR-04]` Xuất Excel (`.xlsx`) & Seed Quy trình Duyệt Công tác:**
  - Xuất danh sách đơn Tăng ca OT (`don-tang-ca-YYYY-MM-DD.xlsx`) và đơn Công tác (`don-cong-tac-YYYY-MM-DD.xlsx`) theo bộ lọc hiện tại & Data Scope, tái sử dụng `buildExcelBuffer`.
  - Bổ sung idempotent quy trình duyệt mặc định `hrm / BUSINESS_TRIP` (`Quy trình duyệt Đơn Công tác (2 cấp)`: Cấp 1 `DEPT_MANAGER` → Cấp 2 `HR_MANAGER`) vào `database/seed-core.ts`.

## 3. Thiết kế Database (`[DB-xx]`)

- **Migration dự kiến:** `database/migrations/20261123_000008_init_hrm_ot_business_trips.sql` (đủ khối `UP` và `DOWN`; chỉ tự chạy trên Local/Dev `localhost`/`127.0.0.1`).
- **Chuẩn bắt buộc:** `InnoDB`, `DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`, `snake_case`, giờ/ngày dùng `DECIMAL(5, 2)`, chi phí dùng `DECIMAL(18, 2)`, đầy đủ audit columns (`created_by`, `updated_by`, `created_at`, `updated_at`, `deleted_at`).

- **`[DB-01]` Bảng `overtime_requests`:**
  - Cột: `id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY`, `request_code VARCHAR(40) NOT NULL`, `employee_id BIGINT UNSIGNED NOT NULL`, `work_date DATE NOT NULL`, `start_time VARCHAR(5) NOT NULL`, `end_time VARCHAR(5) NOT NULL`, `total_hours DECIMAL(5, 2) NOT NULL`, `ot_rate_type ENUM('WEEKDAY_150', 'WEEKEND_200', 'HOLIDAY_300') NOT NULL`, `is_holiday TINYINT(1) NOT NULL DEFAULT 0`, `reason TEXT NOT NULL`, `status ENUM('DRAFT', 'PENDING', 'APPROVED', 'REJECTED', 'CANCELLED') NOT NULL DEFAULT 'DRAFT'`, `approval_request_id BIGINT UNSIGNED NULL`, audit columns.
  - Ràng buộc & Index:
    - `uq_overtime_requests_code (request_code)`
    - `fk_overtime_requests_employee_id` → `employees(id)` (`ON DELETE RESTRICT`)
    - `fk_overtime_requests_approval_request_id` → `approval_requests(id)` (`ON DELETE SET NULL`)
    - `idx_overtime_requests_emp_date (employee_id, work_date)`
    - `idx_overtime_requests_status (status, deleted_at)`
    - `idx_overtime_requests_approval (approval_request_id)`.

- **`[DB-02]` Bảng `business_trip_requests`:**
  - Cột: `id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY`, `request_code VARCHAR(40) NOT NULL`, `employee_id BIGINT UNSIGNED NOT NULL`, `destination VARCHAR(200) NOT NULL`, `start_date DATE NOT NULL`, `end_date DATE NOT NULL`, `total_days DECIMAL(5, 2) NOT NULL`, `purpose TEXT NOT NULL`, `estimated_cost DECIMAL(18, 2) NOT NULL DEFAULT 0.00`, `status ENUM('DRAFT', 'PENDING', 'APPROVED', 'REJECTED', 'CANCELLED') NOT NULL DEFAULT 'DRAFT'`, `approval_request_id BIGINT UNSIGNED NULL`, audit columns.
  - Ràng buộc & Index:
    - `uq_business_trip_requests_code (request_code)`
    - `fk_business_trip_requests_employee_id` → `employees(id)` (`ON DELETE RESTRICT`)
    - `fk_business_trip_requests_approval_request_id` → `approval_requests(id)` (`ON DELETE SET NULL`)
    - `idx_business_trip_requests_emp_dates (employee_id, start_date, end_date)`
    - `idx_business_trip_requests_status (status, deleted_at)`
    - `idx_business_trip_requests_approval (approval_request_id)`.

- **Thứ tự `DOWN`:** `DROP TABLE IF EXISTS business_trip_requests;` → `DROP TABLE IF EXISTS overtime_requests;`.

## 4. Thiết kế Backend / API (`[API-xx]`)

- **`[API-01]` `GET/POST /api/v1/hrm/requests/overtimes`:**
  - **Middleware:** GET (`mine=true`: user đăng nhập; quản trị: `hrm.requests.read` + Data Scope); POST (`hrm.requests.create`) + `zod`.
  - **Request (POST):**
    ```json
    {
      "workDate": "2026-11-28",
      "startTime": "09:00",
      "endTime": "13:00",
      "isHoliday": false,
      "reason": "Triển khai nâng cấp hệ thống cuối tuần",
      "submitNow": true
    }
    ```
  - **Response (`201`):** `{ "success": true, "data": { "overtimeRequest": { "id": 1, "requestCode": "OT-2026-0001", "totalHours": 4, "otRateType": "WEEKEND_200", "status": "PENDING", "approvalRequestId": 12 } } }`.
  - **Error Codes:** `400`, `401`, `403`, `409` (`OT_TIME_OVERLAP`).

- **`[API-02]` `GET/PATCH/DELETE /api/v1/hrm/requests/overtimes/[id]`:**
  - Xem chi tiết (owner hoặc trong Data Scope), sửa khi `DRAFT`, xóa mềm khi `DRAFT`/`CANCELLED`.

- **`[API-03]` `POST /api/v1/hrm/requests/overtimes/[id]/submit` & `POST /api/v1/hrm/requests/overtimes/[id]/cancel`:**
  - Gửi duyệt đơn `DRAFT` → `PENDING` (tạo `approval_requests` loại `OVERTIME`); hủy đơn `DRAFT`/`PENDING` → `CANCELLED`.

- **`[API-04]` `GET /api/v1/hrm/requests/overtimes/export`:**
  - Quyền `hrm.requests.export`, trả binary `.xlsx` (`don-tang-ca-YYYY-MM-DD.xlsx`).

- **`[API-05]` `GET/POST /api/v1/hrm/requests/business-trips`:**
  - **Middleware:** GET (`mine=true` hoặc `hrm.requests.read` + Data Scope); POST (`hrm.requests.create`) + `zod`.
  - **Request (POST):**
    ```json
    {
      "destination": "Chi nhánh TP. Hồ Chí Minh",
      "startDate": "2026-12-03",
      "endDate": "2026-12-05",
      "estimatedCost": 4500000,
      "purpose": "Gặp gỡ đối tác và khảo sát vận hành chi nhánh",
      "submitNow": true
    }
    ```
  - **Response (`201`):** `{ "success": true, "data": { "businessTripRequest": { "id": 1, "requestCode": "CT-2026-0001", "totalDays": 3, "estimatedCost": 4500000, "status": "PENDING", "approvalRequestId": 13 } } }`.
  - **Error Codes:** `400`, `401`, `403`, `409` (`TRIP_DATE_OVERLAP`).

- **`[API-06]` `GET/PATCH/DELETE /api/v1/hrm/requests/business-trips/[id]`:**
  - Xem chi tiết (owner hoặc Data Scope), sửa khi `DRAFT`, xóa mềm khi `DRAFT`/`CANCELLED`.

- **`[API-07]` `POST /api/v1/hrm/requests/business-trips/[id]/submit` & `POST /api/v1/hrm/requests/business-trips/[id]/cancel`:**
  - Gửi duyệt `DRAFT` → `PENDING` (loại `BUSINESS_TRIP`); hủy `DRAFT`/`PENDING` → `CANCELLED`.

- **`[API-08]` `GET /api/v1/hrm/requests/business-trips/export`:**
  - Quyền `hrm.requests.export`, trả binary `.xlsx` (`don-cong-tac-YYYY-MM-DD.xlsx`).

- **`[API-09]` Đăng ký Approval Completion Hooks (`register-module-hooks.ts`):**
  - Đăng ký `'overtime_requests'` và `'business_trip_requests'` vào Core Approval Hook Registry (giữ nguyên tương thích ngược 100% với `'leave_requests'` và `TC-CORE-023`).
