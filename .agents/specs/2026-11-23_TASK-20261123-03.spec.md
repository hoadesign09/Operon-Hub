## 2. Thiết kế Chức năng & Luật Nghiệp vụ (`[FR-xx]`)

- **`[FR-01]` Xác thực JWT & Refresh Token Rotation (`src/modules/auth/`):**
  - Dùng `jose` (`HS256`) ký Access Token (mặc định hết hạn `15m`) lưu vào HttpOnly cookie `operon_access_token` (`SameSite=Lax`, `Path=/`, `Secure` khi `NODE_ENV=production`) và hỗ trợ đọc thêm `Authorization: Bearer <token>`.
  - Refresh Token sinh ngẫu nhiên 32 bytes bằng `generateSecureToken()` (`src/lib/portable/token-hash.ts`), lưu vào HttpOnly cookie `operon_refresh_token` (`7 ngày`) và chỉ lưu bản băm **SHA-256** (`sha256Hex`) vào bảng `refresh_tokens`.
  - Khi gọi `/refresh`: kiểm tra hash khớp DB, `revoked_at IS NULL`, `expires_at > NOW()`, và `user.status === 'ACTIVE'`; đánh dấu `revoked_at = NOW()` cho token cũ và phát hành cặp token mới (Rotation).
  - Tài khoản bị khóa (`LOCKED`) hoặc đã xóa mềm (`deleted_at IS NOT NULL`) bị chặn ngay khi đăng nhập hoặc làm mới phiên (`403` / `401`).

- **`[FR-02]` Middleware Phân quyền RBAC & Data Scope (`src/middlewares/auth.ts`):**
  - Cung cấp `withAuth(handler, options?: { permission?: string })`:
    1. Xác thực Access Token → trả `401 UNAUTHORIZED` nếu thiếu/hết hạn/không hợp lệ.
    2. Nạp thông tin user hiện hành + `roles` + `permissions` + `dataScope` cao nhất (`ALL` > `BRANCH` > `DEPARTMENT` > `OWN`) + `branchIds` được gán (nếu có gán `branch_id = NULL` hoặc là `SUPER_ADMIN` thì `hasAllBranches = true`).
    3. Nếu `options.permission` được khai báo mà user không có quyền (trừ `SUPER_ADMIN` mặc định có toàn quyền) → trả `403 FORBIDDEN`.
  - Truyền `auth: AuthContext` vào handler để mọi service lọc dữ liệu đúng phạm vi.

- **`[FR-03]` Ghi Nhật ký Kiểm toán (`src/modules/audit/audit.service.ts`):**
  - Hàm `recordAuditLog(...)` ghi nhận hành động vào `audit_logs` cho các thao tác nhạy cảm: `AUTH_LOGIN`, `AUTH_CHANGE_PASSWORD`, `BRANCH_CREATE/UPDATE/DELETE`, `USER_CREATE/UPDATE`, `ROLE_PERMISSIONS_UPDATE`.
  - Tuyệt đối **không lưu** `password`, `password_hash`, `refreshToken` vào `old_values`/`new_values`.

- **`[FR-04]` Quản lý Chi nhánh (`src/modules/branches/`):**
  - Mã chi nhánh (`code`) chuẩn hóa chữ hoa không dấu (`^[A-Z0-9_-]{2,30}$`), duy nhất (không trùng bản ghi chưa xóa mềm).
  - Xóa chi nhánh dùng xóa mềm (`deleted_at = NOW()`, `is_active = 0`).
  - **Luật chặn:** Không cho xóa chi nhánh đang là Trụ sở chính (`is_headquarters = 1`) nếu chưa chuyển trụ sở chính sang chi nhánh khác. Khi đặt chi nhánh mới làm `is_headquarters = 1`, tự động bỏ cờ trụ sở chính ở chi nhánh cũ trong cùng transaction.

- **`[FR-05]` Quản lý Tài khoản & Ma trận Phân quyền RBAC (`src/modules/users/`, `src/modules/roles/`):**
  - Tạo tài khoản mới: kiểm tra trùng `email` (`409`), băm mật khẩu qua `hashPassword()` (`src/lib/portable/password-hasher.ts`), gán tối thiểu 1 vai trò trong `user_roles` (trong transaction).
  - Cập nhật tài khoản: cho phép đổi `full_name`, `status` (`ACTIVE`/`LOCKED`), và danh sách `(roleId, branchId)`. **Luật chặn:** Không cho phép người dùng tự khóa (`LOCKED`) chính tài khoản đang đăng nhập (`400`).
  - Cập nhật ma trận quyền cho Role: thay thế tập `permissionIds` trong `role_permissions` bằng transaction. **Luật chặn:** Không cho gỡ quyền khỏi role hệ thống `SUPER_ADMIN` (`400`).

- **`[FR-06]` Seed Khởi tạo Dữ liệu Core Local/Dev (`database/seed-core.ts`):**
  - Bắt buộc gọi `assertLocalDevEnvironment(process.env)` trước khi kết nối MySQL (cấm chạy ngoài Local/Dev).
  - Chạy idempotent (chạy nhiều lần không lỗi trùng):
    - 1 Chi nhánh mặc định: `HQ` — `Trụ sở chính`.
    - 8 Vai trò hệ thống đúng Blueprint §1.2 (`SUPER_ADMIN`, `EXECUTIVE`, `HR_MANAGER`, `HR_STAFF`, `PAYROLL_ACCOUNTANT`, `ADMIN_OPS`, `DEPT_MANAGER`, `EMPLOYEE`).
    - Bộ quyền chuẩn nhóm `core.*` (`core.branches.read/create/update/delete`, `core.users.read/create/update`, `core.roles.read/update`, `core.audit_logs.read`, `core.settings.read/update`) và `hrm.dashboard.read`.
    - 1 tài khoản khởi tạo: `admin@operonhub.local` / `Admin@123456` gán role `SUPER_ADMIN` (`branch_id = NULL`).

## 4. Thiết kế Backend / API (`[API-xx]`)

- **`[API-01]` `POST /api/v1/auth/login`:**
  - **Middleware:** Public + `withErrorHandler` + `zod` (`email`, `password`).
  - **Success (`200`):** Set HttpOnly cookies `operon_access_token` & `operon_refresh_token`; trả `{ success: true, data: { user: { id, email, fullName, status, roles, permissions, dataScope, branches } } }` (không trả `password_hash`).
  - **Errors:** `400` (thiếu/sai định dạng email), `401` (sai email hoặc mật khẩu), `403` (tài khoản bị khóa `LOCKED`).

- **`[API-02]` `POST /api/v1/auth/refresh`:**
  - **Middleware:** Đọc cookie `operon_refresh_token`.
  - **Success (`200`):** Rotate token mới vào cookie, trả `{ success: true, data: { refreshed: true } }`.
  - **Errors:** `401` (token không tồn tại, đã bị thu hồi hoặc hết hạn).

- **`[API-03]` `POST /api/v1/auth/logout`:**
  - **Middleware:** Public/Auth — thu hồi refresh token hiện tại trong DB (nếu có) và xóa sạch 2 cookie auth.
  - **Success (`200`):** `{ success: true, data: { loggedOut: true } }`.

- **`[API-04]` `GET /api/v1/auth/me` & `PATCH /api/v1/auth/change-password`:**
  - **Middleware:** `withAuth` (mọi user đã đăng nhập).
  - **`GET /me` (`200`):** Trả hồ sơ user + `roles` + `permissions` + `dataScope` + danh sách `branches` được phép thao tác + danh sách `modules` đã lọc theo quyền.
  - **`PATCH /change-password` (`200`):** Body `{ currentPassword, newPassword }` (`newPassword >= 8` ký tự, khác mật khẩu cũ). Errors: `400` (mật khẩu hiện tại sai hoặc mật khẩu mới yếu), `401`.

- **`[API-05]` CRUD Chi nhánh (`/api/v1/core/branches`, `/api/v1/core/branches/[id]`):**
  - `GET`: `core.branches.read`, query `page`, `limit`, `search`, `isActive` → `{ success: true, data: [...], meta }`.
  - `POST`: `core.branches.create`, validate `code`, `name`, `taxCode?`, `address?`, `phone?`, `isHeadquarters?`, `isActive?` → `201`. Error `409` nếu trùng `code`.
  - `PATCH /[id]`: `core.branches.update` → `200`. Errors: `400`, `404`, `409`.
  - `DELETE /[id]`: `core.branches.delete` (soft delete) → `200`. Errors: `400` (cố xóa trụ sở chính), `404`.

- **`[API-06]` Quản lý Tài khoản (`/api/v1/core/users`, `/api/v1/core/users/[id]`):**
  - `GET`: `core.users.read`, query `page`, `limit`, `search`, `status` → danh sách user kèm roles/branches (tuyệt đối không trả `password_hash`).
  - `POST`: `core.users.create`, body `{ email, fullName, password, status?, assignments: [{ roleId, branchId? }] }` → `201`. Error `409` nếu trùng `email`.
  - `PATCH /[id]`: `core.users.update`, cập nhật `fullName`, `status`, `assignments` → `200`. Errors: `400` (tự khóa chính mình), `404`.

- **`[API-07]` Quản lý Vai trò & Ma trận Quyền (`/api/v1/core/roles`, `/api/v1/core/permissions`, `/api/v1/core/roles/[id]/permissions`):**
  - `GET /roles`: `core.roles.read` → danh sách roles kèm `permissionIds` và `userCount`.
  - `GET /permissions`: `core.roles.read` → toàn bộ danh sách permissions nhóm theo `module_code`.
  - `PUT /roles/[id]/permissions`: `core.roles.update`, body `{ permissionIds: number[] }` → `200`. Errors: `400` (gỡ quyền `SUPER_ADMIN`), `404`.

- **`[API-08]` Nhật ký Kiểm toán (`GET /api/v1/core/audit-logs`):**
  - **Middleware:** `withAuth({ permission: 'core.audit_logs.read' })`.
  - Query: `page`, `limit`, `moduleCode`, `action` → trả danh sách audit log mới nhất kèm tên người thực hiện.

- **Tương thích ngược:** `GET /api/v1/health` giữ nguyên 100% contract; `src/config/env.ts` bổ sung default dev cho `JWT_*` ở môi trường test/development nhưng vẫn yêu cầu `>= 32` ký tự khi cấu hình thật.
