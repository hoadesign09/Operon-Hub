## 2. Thiết kế Chức năng & Luật Nghiệp vụ (`[FR-xx]`)

- **`[FR-01]` Khởi tạo Dự án Next.js + Cấu hình Scripts & MIT Policy:**
  - **Mô tả:** Thiết lập dự án Next.js App Router + Tailwind CSS v4 + TypeScript (`strict: true`, path alias `@/*` trỏ về `./src/*`), ESLint và Vitest.
  - **NPM Scripts bắt buộc trong `package.json`:** `dev`, `build`, `start`, `lint`, `typecheck`, `test`, `db:migrate`, `db:rollback`, `db:status`.
  - **Ràng buộc MIT:** Mọi package trong `dependencies` và `devDependencies` phải là `MIT`, ngoại trừ duy nhất `typescript` (`Apache-2.0`, `devDependencies`, đã được người dùng duyệt tại Gate 4). Không cài `dotenv` (`BSD-2-Clause`) — sử dụng tính năng nạp `.env` gốc của Node.js (`--env-file-if-exists=.env`) và Next.js.

- **`[FR-02]` Validate Biến Môi trường & Quản lý MySQL Pool (`src/config/`):**
  - **Mô tả:** `src/config/env.ts` đọc và validate biến môi trường bằng `zod` (`NODE_ENV`, `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`, `DB_POOL_LIMIT`, `APP_TIMEZONE`). Báo lỗi tiếng Việt rõ tên biến bị thiếu/sai kiểu khi khởi động.
  - **MySQL Connection (`src/config/database.ts`):** Khởi tạo `mysql2/promise` pool (kèm `charset: 'utf8mb4'`, `decimalNumbers: false` để tránh mất độ chính xác `DECIMAL`, `waitForConnections: true`) gắn vào `Kysely` singleton (tái sử dụng qua `globalThis` ở dev mode tránh rò rỉ connection khi Hot Reload). Cung cấp hàm `getDb()`, `pingDatabase()` (trả `{ ok, latencyMs, error? }`), và `closeDatabase()`.

- **`[FR-03]` Công cụ Migration Runner có Khóa An toàn Môi trường (`database/migrator.ts`):**
  - **Mô tả:** Đọc danh sách file `database/migrations/*.sql` sắp theo thứ tự tăng dần. Mỗi file bắt buộc chứa đúng 2 phân đoạn đánh dấu `-- UP` và `-- DOWN`.
  - **Chế độ lệnh:**
    - `up`: Chạy các migration chưa có trong `schema_migrations` và ghi nhận tên file + `applied_at`.
    - `down`: Rollback đúng **1 migration gần nhất** (chạy phần `-- DOWN` và xóa dòng tương ứng khỏi `schema_migrations`).
    - `status`: In danh sách migration đã chạy (`APPLIED`) và chưa chạy (`PENDING`).
  - **Ngoại lệ & Chặn an toàn (Bắt buộc theo `database-standards.md`):**
    - Nếu `NODE_ENV !== 'development'` **HOẶC** `DB_HOST` không nằm trong `['localhost', '127.0.0.1']` → **chặn ngay lập tức** với exit code `1` và thông báo lỗi rõ ràng (không thực thi SQL).
    - Nếu file `.sql` thiếu phân đoạn `-- UP` hoặc `-- DOWN` (rỗng) → từ chối chạy và báo rõ tên file vi phạm.

- **`[FR-04]` Bộ 5 Tiện ích Tái sử dụng Đa dự án (`src/lib/portable/`):**
  - Mọi file trong `src/lib/portable/` tuyệt đối **không import** `src/config/*`, `src/modules/*` hay biến `process.env` trực tiếp; đầy đủ block JSDoc đầu file (Mục đích, Dependencies, Input/Output, Ví dụ).
  - **`password-hasher.ts`** (Dependencies: `None` — dùng `node:crypto`):
    - `hashPassword(plain, options?)`: Kiểm tra mật khẩu rỗng → ném lỗi rõ ràng; sinh salt ngẫu nhiên 16 bytes; băm bằng `scrypt` (`N=16384, r=8, p=1, keylen=64`); trả về chuỗi chuẩn `scrypt$<N>$<r>$<p>$<saltHex>$<hashHex>`.
    - `verifyPassword(plain, storedHash)`: Parse chuỗi chuẩn, băm lại với salt/params lưu sẵn và so sánh chống timing-attack bằng `crypto.timingSafeEqual`. Trả `false` an toàn nếu sai định dạng hoặc sai mật khẩu.
  - **`date-utils.ts`** (Dependencies: `dayjs`):
    - `formatDateVN(input, fallback = '-')`: Chuyển `Date | string | number | null | undefined` sang `DD/MM/YYYY`; trả `fallback` nếu không hợp lệ.
    - `formatDateTimeVN(input, fallback = '-')`: Trả `DD/MM/YYYY HH:mm`.
    - `countWorkingDays(startDate, endDate, options?)`: Đếm số ngày làm việc trong khoảng `[startDate, endDate]` bao gồm cả 2 đầu, mặc định loại trừ Thứ 7 (`6`) và Chủ nhật (`0`) + mảng `holidays` (`YYYY-MM-DD[]`) truyền vào; trả `0` nếu `endDate < startDate`.
  - **`currency-utils.ts`** (Dependencies: `None`):
    - `roundCurrency(value, decimals = 0)`: Làm tròn an toàn tránh sai số dấu phẩy động (dùng `Number.EPSILON` / chuỗi số).
    - `formatVND(amount, options?)`: Định dạng chuẩn VN (vd: `15.000.000 ₫`, hỗ trợ `showSymbol: false` → `15.000.000`, nhận cả `number | string` từ cột `DECIMAL` MySQL). Trả fallback khi `NaN`/`null`.
    - `parseCurrencyInput(raw)`: Chuyển chuỗi tiền tệ VN (`"15.000.000 ₫"`) về số `number` an toàn, trả `null` nếu không hợp lệ.
  - **`pagination.ts`** (Dependencies: `None`):
    - `parsePaginationParams(query, options?)`: Chuẩn hóa `page` (mặc định `1`, min `1`), `limit` (mặc định `20`, giới hạn `[1, maxLimit=100]`), tính `offset = (page - 1) * limit`, lọc `sortBy` theo `allowedSortFields` (tránh SQL injection trên `ORDER BY`), `sortOrder` chỉ nhận `'asc' | 'desc'`.
    - `buildPaginationMeta(total, page, limit)`: Trả `{ page, limit, total, totalPages, hasNext, hasPrev }`.
  - **`retry.ts`** (Dependencies: `None`):
    - `retryAsync(fn, options?)`: Thử lại hàm async tối đa `retries` lần (mặc định `3`) với `baseDelayMs` (mặc định `200`) nhân theo hàm mũ (`backoffFactor = 2`), hỗ trợ `shouldRetry(error, attempt)`.

- **`[FR-05]` Khung Module Registry (`src/modules/registry.ts`):**
  - **Mô tả:** Khai báo cấu trúc kiểu `PortalModuleDefinition` (`code`, `name`, `description`, `basePath`, `status`: `'ACTIVE' | 'COMING_SOON' | 'DISABLED'`, `order`) và danh sách mặc định: `core` (ACTIVE), `hrm` (ACTIVE), `crm` (COMING_SOON). Cung cấp hàm thuần `getVisibleModules(includeComingSoon?)` để UI và Sidebar dùng chung từ `TASK-02` trở đi.

## 3. Thiết kế Database (`[DB-xx]`)

- **`[DB-01]` Bảng `schema_migrations` (Quản lý phiên bản Migration — tự khởi tạo bởi `database/migrator.ts`):**
  - `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`
  - Cột:
    - `id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY`
    - `filename VARCHAR(255) NOT NULL` — Unique `uq_schema_migrations_filename`
    - `applied_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP`

- **`[DB-02]` Bảng `settings` (Bảng Core cấu hình hệ thống theo Blueprint §3.2):**
  - **File Migration:** `database/migrations/20261123_000001_init_settings.sql` (có đầy đủ `-- UP` và `-- DOWN`).
  - `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`
  - Cột & Ràng buộc:
    - `id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY`
    - `module_code VARCHAR(50) NOT NULL DEFAULT 'core'`
    - `setting_key VARCHAR(120) NOT NULL` — Unique `uq_settings_setting_key`
    - `setting_value JSON NOT NULL`
    - `description VARCHAR(255) NULL`
    - `created_by BIGINT UNSIGNED NULL`
    - `updated_by BIGINT UNSIGNED NULL`
    - `created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP`
    - `updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP`
    - `deleted_at TIMESTAMP NULL DEFAULT NULL`
  - Index:
    - `uq_settings_setting_key (setting_key)`
    - `idx_settings_module_code (module_code)`
    - `idx_settings_deleted_at (deleted_at)`
  - **`-- DOWN`:** `DROP TABLE IF EXISTS settings;` (chỉ dùng cho rollback migration trên Local/Dev khi test `db:rollback`).
  - **Lưu ý thực thi ở Phase 2:** Chỉ chạy `npm run db:migrate` nếu máy Local đang có MySQL chạy tại `localhost`/`127.0.0.1` và cấu hình `.env` hợp lệ; nếu MySQL Local chưa khởi tạo DB, báo rõ hướng dẫn tạo database để người dùng xác nhận (không tự đoán thông tin DB ngoài local).

## 4. Thiết kế Backend / API (`[API-xx]`)

- **`[API-01]` `GET /api/v1/health` (`src/app/api/v1/health/route.ts`):**
  - **Middleware:** Public (không yêu cầu Auth — dùng cho health check hệ thống và màn hình khởi tạo); bọc `withErrorHandler` chuẩn hóa lỗi; đặt `export const dynamic = 'force-dynamic'` để không bị cache tĩnh.
  - **Request:** Không có tham số đầu vào.
  - **Response Success (`200 OK` — Khi MySQL kết nối bình thường):**
    ```json
    {
      "success": true,
      "data": {
        "app": "Operon Hub",
        "version": "1.0.0",
        "status": "HEALTHY",
        "environment": "development",
        "timestamp": "2026-11-23T04:30:00.000Z",
        "database": {
          "status": "UP",
          "latencyMs": 4
        },
        "modules": [
          { "code": "core", "name": "Nền tảng Hệ thống", "status": "ACTIVE" },
          { "code": "hrm", "name": "Hành chính Nhân sự (HRM)", "status": "ACTIVE" },
          { "code": "crm", "name": "Quan hệ Khách hàng (CRM)", "status": "COMING_SOON" }
        ]
      }
    }
    ```
  - **Response Degraded (`503 Service Unavailable` — Khi chưa kết nối được MySQL hoặc thiếu cấu hình DB):**
    ```json
    {
      "success": false,
      "error": {
        "code": "DATABASE_UNAVAILABLE",
        "message": "Không thể kết nối tới cơ sở dữ liệu MySQL. Vui lòng kiểm tra cấu hình và dịch vụ DB."
      },
      "data": {
        "app": "Operon Hub",
        "version": "1.0.0",
        "status": "DEGRADED",
        "timestamp": "2026-11-23T04:30:00.000Z",
        "database": {
          "status": "DOWN",
          "latencyMs": null
        },
        "modules": []
      }
    }
    ```
  - **Bảo mật:** Tuyệt đối **không trả về** `DB_PASSWORD`, `DB_USER`, `DB_HOST` hay stack trace lỗi nội bộ ra response JSON.
  - **Tương thích ngược:** Endpoint mới hoàn toàn.

  - **Responsive:** Bố cục 1 cột trên Mobile (`< 768px`), lưới 2–3 cột trên Tablet/Desktop (`>= 768px`).
